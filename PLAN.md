# План развития «Фабрики гипотез»

Три шага поверх рабочего гибридного ядра (детерминированная ветка А + LLM-ветка Б).
Агента и FastAPI-обвязку — потом, отдельно.

## 1. Модуль «мировые практики» (веб-поиск)  ✅ ГОТОВО
Заполняет поле `world_practice` каждой гипотезы внешним подтверждением из промышленности.
- [x] `factory/websearch.py`: поиск → загрузка страниц → LLM-выжимка с цитатным гейтом (URL + дословная цитата), кэш по отпечатку запроса (воспроизводимо).
- [x] Приоритет промышленных/материаловедческих источников (allowlist: NIMS MITS, SAIMM, MDPI Minerals, ScienceDirect, Metso/Outotec, CEEC…).
- [x] Двуязычно: ищем и на русском, и на английском; LLM понимает EN-материалы и резюмирует на RU.
- [x] Встроить в `flex.py` как опциональный шаг `--web` (до записи HTML), показать в отчёте `report.py` (цитата + кликабельный источник).
- [x] Деградация без сети/ключа → `world_practice=None` (не выдумываем); недоступные страницы (403/таймаут) молча пропускаются.
- Проверено end-to-end: находит реальную практику с дословной цитатой и URL (напр. доизмельчение промпродукта → упоминание конкретной обогатительной фабрики).
- Запуск: `uv run python -m factory.flex materials --kpi "…" --web`

## 2. Критик (LLM-рассуждение над гипотезой)
Не влияет на скор — помощь ресёрчеру. Рядом с детерминированными метриками.
- [ ] `factory/critic.py`: по гипотезе LLM пишет разбор (риски, слабые места, что проверить),
      БЕЗ выставления чисел (LLM плохо и случайно ставит цифры — числа остаются за метриками).
- [ ] Показать критику отдельным блоком в HTML; включается флагом.

## 3. OCR — обязательно связать и улучшить
Картинки ужасного качества, но там ключевая инфа по процессам.
- [ ] Предобработка перед OCR: grayscale, автоконтраст, upscale, бинаризация/деноизинг.
