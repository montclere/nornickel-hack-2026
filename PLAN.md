# План развития «Фабрики гипотез»

Ядро (детерминированная ветка А + LLM-ветка Б) готово и оттестировано. Дальше — веб-сервис
и точечные улучшения. Принцип прежний: одна крепкая фича > кучи сырых; детерминизм в
рассуждении, LLM только в понимании текста (с цитатным гейтом).

## ✅ Сделано (кратко)
- Веб-практики (`--web`) — ДЕТЕРМИНИРОВАННО, без LLM, с гейтом качества (не заголовки), RU-соседи.
- Досье OpenAlex (`--dossier`) — статьи + цитируемость + фраза-причина, без LLM/ключа.
- Единый клиент внешних вызовов `client.py` + телеметрия (`run_metrics.json`), circuit-breaker.
- OCR-предобработка `imageprep.py` (grayscale/автоконтраст/апскейл).
- Эксперимент = тест/метрика/критерий; roadmap (лаб→пилот→внедрение); litsupport (цитаты корпуса);
  feedback (ре-ранк эксперта); export (JSON/CSV/Jira/PDF/DOCX); report_kb (HTML ветки Б).
- Отчёт: чистка воды/эмодзи, источник+бейджи прогона, метрики внизу, ховер, провенанс до ячейки.
- Materials → `data/` (state) / `knowledge/` (reference); preflight LLM/OCR (без зависаний).

## 1. Веб-сервис на FastAPI  ← ДЕЛАЕМ СЕЙЧАС
Локальный инстанс (НЕ публичный) для тестирования жюри. Обёртка над готовым ядром;
LLM-части деградируют мягко через preflight. Ставится: `uv sync --extra web`.

### Архитектура (плоская, слоями) — папка `webapp/`
```
webapp/
  main.py            фабрика приложения (роутеры, static, templates, lifespan)
  config.py          настройки + ЛИМИТЫ (размер/типы файлов, локальность)
  di.py              провайдеры зависимостей (интерфейс → реализация)
  interfaces/        Protocol-контракты: LLMClient, SearchClient
  adapters/          реализации: yandex_llm, ddg_search, yandex_search (заглушка под замену)
  infra/             storage (run_id-папки), uploads (multipart, split data/knowledge)
  services/          RunService (оркестрация пайплайна), ReportService (чтение результатов)
  api/schemas.py     pydantic-контракты запрос/ответ
  api/routes/        health, runs, files, pages (Jinja)
  templates/         index (drag-drop), run (карточки), card (деталь)
  static/            app.css, app.js (htmx + ванильный JS)
```

- [ ] **Интерфейсы + DI:** `LLMClient`/`SearchClient` как Protocol; адаптеры Yandex/DDG;
      заглушка `yandex_search` (чтобы заменить DDG на Yandex Search API одним провайдером).
      Проброс через FastAPI `Depends` (Dishka — опциональный апгрейд до контейнерного DI).
- [ ] **Изоляция прогонов:** каждый запуск → `outputs/runs/<run_id>/` (загрузки в `sources/`,
      отчёты/контекст/метрики рядом). Ничего в БД — эфемерно, локально.
- [ ] **Роуты:** `POST /api/runs` (загрузка+KPI+флаги → run_id), `GET /runs/{id}` (карточки),
      `GET /runs/{id}/hyp/{rank}` (деталь), `GET /runs/{id}/sources/{path}` (открыть исходник),
      `GET /health` (доступность LLM/OCR/поиска — preflight).
- [ ] **Стартовый экран:** drag-n-drop с разделением **данные/знания**, поле KPI, ограничения
      (учитываются: «без нового оборудования» — детерминированно в intent.py; богатый
      свободный текст — LLM-трек), чекбоксы `--dossier/--web`.
- [ ] **Карточки:** главная — компактные карточки гипотез (не хламить); клик → деталь.
      Всё прокликиваемо; клик по цитате/ячейке → исходник открывается в новой вкладке
      НА НУЖНОМ МЕСТЕ (`sources/<file>#page=N`).
- [ ] **Визуал:** Jinja2 рендерит (графы — inline SVG), интерактив — htmx + ванильный JS.
- [ ] **Docker:** Dockerfile + compose; локальный запуск `uvicorn`.
- [ ] **Ограничения (написать):** локальный инстанс, не публичный; данные фабрик наружу не
      уходят (только термины запроса к подтверждённым источникам); нет аутентификации/
      многопользовательской изоляции по безопасности (только по run_id); лимиты на размер загрузки.
