# Бейзлайн 02 · Диагностика по хвостам обогащения

**Это главный бейзлайн — он работает на РЕАЛЬНЫХ данных заказчика и воспроизводит
гипотезы, которые инженеры получили мозговым штурмом.**

## Что демонстрирует

Система читает сырой Excel-отчёт института по хвостам, сама находит, **где** (в каком
классе крупности) и **почему** (недоизмельчение сростков vs шламы) теряется
**извлекаемый** металл, и формирует проверяемые инженерные гипотезы, ранжированные по
**ценности = тонны металла в риске** (→ деньги). Каждое число заземлено до **ячейки
Excel**, каждая гипотеза — до источника (справочник флотации + инструкция по чтению отчёта).

## Откуда данные

`data/` — обезличенные отчёты из архива кейса «Задача 1. Фабрика гипотез»:
- `Хвосты *.xlsx` — 4 реальных отчёта по фабрикам (КГМК, НОФ вкр, НОФ мед, ТОФ):
  содержание элементов **28 (Ni) / 29 (Cu)** по классам крупности `+125 … -10 мкм`,
  минералогия (раскрытый / закрытый пентландит `Pnt`, `Cp`, миллерит), доля извлекаемого.
- `Гипотезы *.docx` — **эталонные** гипотезы мозгового штурма инженеров (для сверки).
- `Как читать отчёт …docx` — инструкция заказчика (что такое хвосты, извлекаемые формы).

Парсинг — только stdlib (`zipfile`+`re`), без pandas/openpyxl. Читаются кэшированные
значения ячеек; битые формулы (`#REF!`) гасятся.

## Запуск

```bash
python run.py                                    # все 4 фабрики, конфиг по умолчанию
python run.py "Хвосты ТОФ_2.xlsx"                # одна
python run.py --config config.flotation.json     # явный доменный конфиг
```

Весь домен — в `config.flotation.json` (роли колонок, якоря-подписи, элементы+цены,
маршрутизация классов, библиотека вмешательств с источниками). В `run.py` доменных строк нет.

## Что говорить на защите

1. **«Мы не сочиняем — мы диагностируем данные заказчика.»** Логика прозрачна: извлекаемый
   металл × класс крупности → семейство вмешательства. Крупный класс + закрытый Pnt (в ТОФ
   66.9%) = недораскрытие → измельчение/классификация. Тонкий класс `-10` = шламы →
   грохочение/гидроциклоны/время флотации.
2. **Reproduction как доказательство.** Подаём сырой Excel → система независимо покрывает
   **все гипотезы мозгового штурма** по семейству вмешательства (ТОФ 8/8, НОФ 8/8, КГМК 5/5)
   — и приоритизирует их тоннажем, чего в `.docx` нет. Это hackathon-эквивалент бэктеста:
   «красиво» → «доказанно воспроводит эксперта из цифр».
3. **Ценность в деньгах.** Value — не абстрактный скор, а тонны Ni/Cu в риске × цена.
4. **Не хардкод — физически.** В `run.py` нет доменных строк: элементы, цены, якоря
   парсинга, правила маршрутизации и библиотека вмешательств вынесены в
   `config.flotation.json`. Другой отчёт/домен = другой конфиг (`--config ...`), код не
   меняется. Табличный «контракт» (подписи-якоря + роли колонок) — это доменный адаптер к
   формату конкретного отчёта, а не логика движка.

> Честная оговорка для жюри: сверка идёт на уровне **семейства** вмешательства (2 семейства),
> поэтому покрытие высокое. Сила не в «угадали дословно», а в том, что система **сама
> локализует потерю в нужный класс/механизм и ранжирует по тоннажу** — то, на что у инженера
> уходит мозговой штурм.

## Критерии кейса

вход (структурные данные) · проверяемость · обоснование+ценность · интерпретируемость
(до ячейки) · гибкость входных данных (Excel) · снижение субъективности.

## Где агент-поисковик

`research(query)` (шаг 7) — сюда подключается доисследование топ-гипотезы: свежая
