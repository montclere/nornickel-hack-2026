# ОСНОВНОЙ бейзлайн · Автоматическая grounded-фабрика гипотез

**Полностью автоматический пайплайн. Человек делает ровно две вещи: кладёт файлы в
папку и пишет KPI. Никаких конфигов, фактов, схем или библиотек вмешательств руками.**

## Конвейер (всё авто)

```
папка материалов ──► ПРИЁМ ──► ЗНАНИЕ ──► НОВИЗНА ──► ГЕНЕРАЦИЯ ──► КРИТИК ──► ОЦЕНКА+РАНГ
   (PDF/XLSX/       парсинг   LLM+цитат-  эмбеддинги   RAG-LLM      grounding  измеримая
    DOCX/TXT)       любых     ный гейт    (карта       строго по    -гейт      новизна +
                    файлов                известного)  фактам                  value/risk
```

1. **Приём** — [common/ingest.py](../common/ingest.py): авто-парсинг PDF (pymupdf),
   XLSX (openpyxl), DOCX/TXT. Каждый фрагмент несёт провенанс (файл + страница/лист).
2. **Знание** — [common/extract.py](../common/extract.py): LLM извлекает граф причинно-
   следственных связей; **цитатный гейт** отбрасывает всё, что не подтверждено дословной
   цитатой из источника. Извлечение фокусируется на релевантных KPI страницах
   (retrieve-then-extract), а не на случайных.
3. **Новизна** — каждая связь векторизуется (эмбеддинги Yandex) → «карта известного».
4. **Генерация** — по KPI извлекаем релевантные связи и просим LLM собрать гипотезы
   СТРОГО из них (RAG, grounded), с полем `uses_facts`.
5. **Критик** — гипотеза без ссылки на реальные извлечённые факты помечается ⚠.
6. **Оценка** — **измеримая новизна** = расстояние гипотезы до ближайшего известного
   факта (показываем и сам ближайший факт), плюс value/risk. Ранг = ценность·надёжность·новизна.

## Что подаёт человек

```bash
uv run python run.py --materials <папка> --kpi "<цель>"
```
Всё. `--materials` — любые файлы (научные PDF, отчёты, Excel с данными). `--kpi` — строка цели.

Пример (демо-корпус в `../materials`: справочник по флотации + инструкция по отчёту + Excel хвостов):
```bash
uv run python run.py --materials ../materials \
  --kpi "снизить потери никеля с отвальными хвостами флотации"
```

## Почему это отвечает на «уберите ручное»

- **Граф знаний не пишется руками** — извлекается LLM из документов с цитатной проверкой.
- **Новизна не заявляется, а вычисляется** — эмбеддинг-расстояние до ближайшего известного.
- **Ноль доменных конфигов** — сменил папку материалов и KPI → другой домен, код тот же.
- **Провенанс до страницы/ячейки** — каждый факт кликается до источника (не чёрный ящик).

## Что говорить на защите

1. «Загрузи материалы + KPI → ранжированные проверяемые гипотезы. Больше человек ничего
   не настраивает.»
2. Grounding-контракт: цитатный гейт при извлечении + critic-гейт при генерации — LLM
   физически не может протащить факт, которого нет в источниках.
3. Измеримая новизна с показом ближайшего аналога — прямо из требований кейса.
4. Универсальность: один код, любой корпус/домен (флотация → материаловедение → полимеры).

## Ограничения (честно)

- Сканы без текстового слоя требуют OCR (помечаются `needs_ocr`) — не подключён.
- Для скорости демо извлечение идёт по top-N релевантных фрагментов (`--max-chunks`);
  в проде обрабатывается весь корпус, результат кэшируется.
- Качество связей зависит от качества источников (мусор на входе → мусор в графе; поэтому
  цитатный гейт и провенанс обязательны).
