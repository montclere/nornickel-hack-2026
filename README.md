# 🏭 Фабрика гипотез

**Из отчётов, книг и сканов схем — проверяемые гипотезы улучшения производства.
С доказательством у каждой цифры. За минуты, а не недели.**

## Что это

Система принимает **цель обычным текстом** («снизить потери никеля с хвостами, без
нового оборудования») и **любые файлы** — Excel-отчёты, PDF/DOCX-литературу, сканы
схем флотации — и выдаёт **ранжированный список гипотез**: что сделать, почему это
сработает, как проверить и как внедрять.

Ключевой принцип — **не чёрный ящик**:

| | Трек А · детерминированный | Трек Б · LLM-анализ |
|---|---|---|
| Что делает | диагностика Excel-отчётов по хвостам | извлечение знаний из литературы и сканов |
| LLM | **не используется вообще** | только читает текст |
| Доказательство | каждое число → **ячейка отчёта** (кликабельно) | каждая связь → **дословная цитата + файл + страница** (клик открывает PDF на нужном месте) |
| Воспроизводимость | байт в байт: тот же файл → тот же результат | цитатный гейт в коде: связь без цитаты отбрасывается; ранжирование детерминировано |
| Скорость | **~0.02 с** на фабрику | минуты (LLM + веб) |

Обе ветки обогащаются внешними доказательствами: **мировые практики** (веб-поиск →
дословная цитата + URL), **научные статьи** (OpenAlex, с цитируемостью), цитаты из
загруженной базы знаний.

## Возможности

- 🎯 **KPI и ограничения свободным текстом** — «без нового оборудования», «без реагента X»,
  «сохранить качество концентрата»: конфликтующие гипотезы штрафуются ×0.1, но честно
  показываются (ограничения бывают переговорными)
- 🔗 **Заземление до источника** — ячейка Excel `E205`, страница PDF `#page=34`, URL с
  дословной цитатой; гипотеза без источника не может появиться по построению
- 🗺 **Дорожная карта внедрения** — лаборатория → пилот на одной секции → тираж,
  с критериями «го/стоп» на каждом этапе
- 👨‍🔬 **Обучение на фидбэке без ML** — эксперт ставит вердикт на карточке
  («полезно / неверно / уже пробовали»), следующий запуск переранжирует прозрачными
  множителями; база вердиктов редактируется на странице `/expert`
- 📊 **Экспорт** — PDF, DOCX, CSV (для правок эксперта в Excel), JSON, задачи Jira
- 📦 **Батч-режим** — весь набор KPI × все фабрики одной командой + сводный CSV
- 🔒 **Приватность** — локальный инстанс; данные фабрик наружу не уходят (только
  обезличенные поисковые термины), подробнее в [LIMITATIONS.md](LIMITATIONS.md)

## Быстрый старт

### 1. Установка

```bash
git clone <repo> && cd nornickel-hack-2026
uv sync --extra web          # зависимости ядра + веб-интерфейс
cp .env.example .env         # ключи (см. ниже)
```

`.env` (не попадает в git). Без ключа работает трек А и веб-поиск через DDG;
LLM-трек, OCR сканов и Yandex-поиск требуют ключ Yandex Cloud:

```
YANDEX_API_KEY=...        # роли: ai.languageModels.user, ai.vision.user, search-api.executor
YANDEX_FOLDER_ID=...
```

### 2. Веб-интерфейс (рекомендуемый путь)

```bash
uv run uvicorn webapp.main:app --host 127.0.0.1 --port 8000
# → http://127.0.0.1:8000
```

или в Docker: `docker compose up --build`

**Сценарий:** перетащите файлы в три зоны (данные фабрики / литература / схемы и
сканы) → напишите цель и ограничения → «Построить гипотезы» → живой экран этапов →
результаты в двух треках, с кликабельными источниками, экспортом и оценкой эксперта.

### 3. CLI (то же ядро)

```bash
# одна фабрика → консоль + HTML + экспорт во все форматы
uv run python -m factory "materials/Задача 1. Фабрика гипотез/Задача 1/Пример 4/Хвосты ТОФ_2.xlsx" \
  --kpi "снизить потери никеля с хвостами" --export all

# полный прогон: диагностика всех фабрик + LLM-чтение литературы + веб-практики
uv run python -m factory.flex materials --kpi "снизить потери никеля" --web

# батч: список KPI × все фабрики → сводка CSV (под held-out набор жюри)
uv run python -m factory.batch kpi_list.txt "materials/Задача 1. Фабрика гипотез" --html
```

Все результаты — в `outputs/` (веб-прогоны — в `outputs/runs/<id>/`).

## Как это работает

```
                 ФАЙЛЫ: xlsx · PDF · DOCX · сканы схем (PNG/JPG)
                                   │
                     ПРИЁМ + OCR (Yandex Vision + предобработка сканов)
                                   │
        ┌──────────────────────────┴─────────────────────────┐
        ▼                                                    ▼
  ТРЕК А · детерминированный                      ТРЕК Б · LLM-анализ
  reader: парсинг по JSON-схеме формата           extract: LLM читает фрагменты,
  → профиль потерь (класс × форма × тонны,        возвращает связи ТОЛЬКО с дословной
    провенанс-ячейка)                             цитатой (цитатный гейт в коде)
  → rules: читаемая таблица правил                → kgraph: граф знаний
  → metrics: impact·addressability·clarity        → discover: разрывы Свонсона +
  → generator: ЕСЛИ/ТО/ПОТОМУ ЧТО + второе          прямые рычаги; ранжирование
    направление класса                              детерминированное
        └──────────────────────────┬─────────────────────────┘
                                   ▼
       ОБОГАЩЕНИЕ: мировые практики (Yandex Search → цитата+URL, фолбэк DDG)
       · научные статьи (OpenAlex + цитируемость) · цитаты из базы знаний
       · дорожная карта · фидбэк эксперта (персистентный ре-ранк)
                                   ▼
       ВЫХОД: веб-карточки (2 трека) · HTML-отчёты · PDF/DOCX/CSV/JSON/Jira
```

Полная логика модулей — в докстрингах (`factory/*.py`), гайд — `factory/docs/build_guide.py`.

## Метрики

| Метрика | Значение | Как получено |
|---|---|---|
| Recall по эталонам инженеров | **100% (27/27)** | golden-бенчмарк по 4 фабрикам брифа, эталоны системе не подсказывались (`factory.benchmark --no-judge`) |
| Заземление (grounding) | **100%** | каждая гипотеза трека А привязана к ячейкам; трек Б — к цитатам (гейт в коде) |
| Диагностика одной фабрики | **~0.02 с** | детерминированное ядро, без сети |
| Полный прогон (LLM + веб) | ~2–3 мин | ТОФ + учебник, живой замер |
| Батч 6 пар KPI×фабрика | 0.22 с | `factory.batch` (ядро) |
| OCR сканов | **+16% текста** | A/B предобработки на реальном регламенте брифа |
| Автотесты | 11 passed | `uv run python -m unittest discover tests` |

Качественная оценка — LLM-as-judge по 5 осям (`factory.judge`), телеметрия всех
внешних вызовов — на странице результатов и в `outputs/run_metrics.json`.

## Структура проекта

```
factory/                          # ядро (используется и CLI, и вебом)
  schema.py schema_bootstrap.py     конфиг формата отчёта (JSON) + LLM-бутстрап новой схемы
  intent.py                         разбор KPI и ограничений (детерминированно, без LLM)
  reader.py analysis.py rules.py    трек А: парсинг → кривая раскрытия → правила диагностики
  metrics.py generator.py           метрики и сборка гипотез (+ «второе направление» класса)
  roadmap.py                        дорожная карта: лаборатория → пилот → внедрение
  ingest.py ocr.py imageprep.py     приём файлов, Yandex OCR, предобработка сканов
  extract.py kgraph.py discover.py  трек Б: LLM-извлечение (цитатный гейт) → граф → Свонсон
  litsupport.py                     цитаты из загруженного корпуса на карточках трека А
  websearch.py openalex.py          мировые практики (Yandex Search + DDG-фолбэк), статьи
  feedback.py                       вердикты эксперта → персистентный прозрачный ре-ранк
  export.py batch.py                PDF/DOCX/CSV/JSON/Jira; батч по набору KPI
  report.py report_kb.py glossary.py  HTML-отчёты обоих треков + глоссарий метрик
  evaluate.py benchmark.py judge.py   golden-бенчмарк, сводный евал, LLM-судья
  pipeline.py flex.py client.py       оркестраторы; единый HTTP-клиент с телеметрией
webapp/                           # FastAPI: тонкий слой над factory (ядро не дублируется)
  api/routes/                       страницы, прогоны, экспорт, файлы, эксперт, health
  services/                         RunService (оркестрация прогона), ReportService
  adapters/ interfaces/ di.py       LLM/поиск за интерфейсами — заменяются на self-hosted
  templates/ static/                Jinja2 + ванильный JS, шрифт Ubuntu вшит локально
tests/                            # unittest, офлайн, без ключей
materials/                        # данные кейса (вне git)
outputs/                          # результаты, кэши, база фидбэка (вне git)
```

## Конфигурация

Всё настраивается через env / `.env` (полный список — `factory/config.py`,
`webapp/config.py`). Ключевое:

| Переменная | Дефолт | Что делает |
|---|---|---|
| `YANDEX_API_KEY` / `YANDEX_FOLDER_ID` | — | LLM, OCR, Yandex Search (роли — см. Быстрый старт) |
| `FACTORY_WEB` / `FACTORY_OCR` | `1` | выключатели веб-поиска и OCR |
| `FACTORY_FEEDBACK` | `1` | учёт вердиктов эксперта (база `outputs/feedback.json`) |
| `FACTORY_SECONDARY_SHARE` | `0.30` | порог «второго направления» класса (подобран по бенчмарку) |
| `WEB_FETCH_WORKERS` / `WEB_HYP_WORKERS` | `8` / `3` | параллельность веб-поиска |
| `JUDGE_MODEL` | = основной | модель LLM-судьи (лучше отличная от экстрактора) |
| `WEBAPP_RUNS_DIR` | `outputs/runs` | где живут веб-прогоны |

KPI **намеренно не имеет дефолта** — цель всегда задаёт пользователь явно.

→ `outputs/batch/сводка.csv` + отчёты по каждому KPI.

## Безопасность и ограничения

Локальный инстанс, не публичный сервис. Данные фабрик наружу не уходят: во внешние
API отправляются только обезличенные поисковые термины и фрагменты **литературы**
(не производственных данных). LLM заменяется на self-hosted через интерфейс
`LLMClient`. Честный список ограничений — [LIMITATIONS.md](LIMITATIONS.md),
планы — [PLAN.md](PLAN.md).
