# Фабрика гипотез — по хвостам обогащения

Вход: Excel-отчёт по хвостам флотации (распределение металла по классам крупности и
минеральным формам). Выход: ранжированный список проверяемых R&D-гипотез — где теряется
металл, в какой форме, что сделать, с экспериментом и дорожной картой. Под каждым числом —
ссылка на ячейку отчёта; под каждой цитатой из литературы — дословный фрагмент со страницей.

**Главный принцип.** Ядро рассуждает **детерминированно** (тот же вход → тот же выход,
воспроизводимо, объяснимо). LLM используется **только чтобы понять текст** литературы/сканов,
и любая извлечённая связь принимается лишь при наличии **дословной цитаты** в источнике
(цитатный гейт) — галлюцинация не проходит. LLM не участвует в ранжировании и метриках.

---

## Как запускать

```bash
uv sync                      # зависимости ядра
# один отчёт → HTML + карточки:
uv run python -m factory "materials/data/fabrics/ТОФ/Хвосты ТОФ_2.xlsx" \
    --kpi "снизить потери никеля" [--export all]
# эталонный бенчмарк по всем фабрикам (детерминированно, без LLM):
uv run python -m factory.evals.benchmark --no-judge materials/data/fabrics
# веб-сервис (локальный, для жюри):
uv sync --extra web && uv run uvicorn webapp.main:app
```

Ключи LLM/OCR/поиска — в `.env` (`YANDEX_API_KEY`, `YANDEX_FOLDER_ID`). Без ключей ветка А
(хвосты) работает полностью; ветка Б (литература) и полировка текста мягко отключаются.

## Архитектура: два трека + веб-обвязка

```
factory/                       ЯДРО (детерминированное, автономное)
├─ Трек А — из ДАННЫХ по хвостам (работает всегда, без ключей)
│   reader → schema           чтение Excel по схеме формата → профиль потерь
│   knowledge, analysis        граф профиля + кривая раскрытия/формы
│   rules → generator → metrics  диагноз(класс×форма) → гипотезы → безразмерные метрики
│   roadmap                    дорожная карта лаборатория→пилот→внедрение
│   intent                     разбор KPI: целевой металл + ограничения
│
├─ Трек Б — из ЛИТЕРАТУРЫ (нужен LLM)
│   ingest → extract           материалы → фрагменты → связи A→B с цитатным гейтом
│   kgraph → discover          граф знаний → разрывы Свонсона + прямые связи → гипотезы
│
├─ A×B (bridge)                диагноз трека А × узлы схемы фабрики из трека Б → конкретика
│
├─ Обогащения (детерминированные, с цитатным гейтом)
│   websearch                  веб-поиск похожих практик (дословная цитата)
│   openalex                   досье научных статей по гипотезе (цитируемость)
│   litsupport                 привязка цитат корпуса к карточкам трека А
│
├─ Оформление
│   report, report_kb          HTML-отчёты (граф-SVG + карточки)
│   export                     JSON/CSV/Jira-задачи/PDF/DOCX (единый слой serialize)
│   glossary                   объяснялка «как читать граф/кривую/метрики»
│
├─ Оценка/эксплуатация
│   evaluate, benchmark        покрытие эталона организаторов + сводный евал
│   judge                      LLM-судья (5 осей 1..5) — оценочный слой, не в ранге
│   feedback                   вердикты эксперта → детерминированный ре-ранк
│   flex, batch                гибкий приём «что угодно» / прогон набора KPI
│
└─ Внешний слой и настройки
    client                     единая точка ВСЕХ внешних вызовов + метрики/ретраи
    llm, ocr, imageprep        клиенты Yandex + препроцессинг картинок
    config                     ВСЕ константы (env-override) — единственное место правки

webapp/                        локальный FastAPI-сервис поверх ядра
    services/run_service       оркестрация одного прогона (ветки А/Б + обогащения)
    api/routes, templates      страницы/загрузка/отдача файлов, Jinja + ванильный JS
    adapters, interfaces, di   Yandex/DDG через интерфейсы (подмена в тестах)
```

**Поток А→Я (веб-прогон):** приём файлов → `intent` (металл/ограничения) → для каждого
xlsx `HypothesisFactory` (reader→generator→metrics, порог топ-N) → веб/досье обогащение →
если есть LLM и неструктурные файлы: ветка Б (extract→discover) + litsupport + A×B со схемой
→ `serialize` → карточки/деталь/экспорт. Нет LLM → детерминированные ветки отдаются как есть.

## Модули по одному — суть и честная ценность

### Трек А (детерминированный)
- **reader.py** — читает Excel по `ReportSchema`: классы крупности, тоннаж металлов,
  минеральные формы, флаг «извлекаемо». Сердце достоверности: всё дальнейшее — из этих ячеек.
  *Достойно:* привязка каждого числа к ячейке. *Слабо:* завязан на известный формат (см. schema).
- **schema.py / schema_bootstrap.py** — всё формат-специфичное знание вынесено в схему;
  bootstrap предлагает схему для незнакомого отчёта через LLM (разовая задача, не в пайплайне).
  *Достойно:* формат не захардкожен в логике. *Слабо:* незнакомый формат без bootstrap не прочтётся.
- **rules.py** — прозрачные доменные правила: доминирующая форма × крупность → семейство
  вмешательства + список интервенций. Закрытый Pnt→измельчение; раскрытый тонкий→шламы;
  раскрытый крупный→доизвлечение флотацией; иная форма→реагентный режим.
  *Достойно:* металлургически корректная логика, читаемая экспертом. *Слабо:* интервенции
  абстрактны («доизмельчить класс»), не привязаны к узлам конкретной фабрики.
- **generator.py** — собирает гипотезы: на каждый класс — диагноз, метрики, эксперимент,
  дорожная карта; металлы Ni/Cu раздельно; `breadth` раскрывает ветви диагноза (разнообразие),
  `max_hyps` — порог топ-N. *Достойно:* весь текст выводится из данных. *Слабо:* при breadth=0
  выдаёт ~2 уникальных вмешательства (монотонно, но честно отражает руду).
- **metrics.py** — безразмерные метрики (не деньги): `impact` (доля извлекаемых потерь
  фабрики на класс), `addressability` (излечимая доля), `clarity` (доминирование одной формы),
  `confidence` (полнота данных), `feasibility` (нужно ли оборудование). Свёртка — открытая формула.
  *Достойно:* прозрачно и воспроизводимо. *Слабо:* веса свёртки эвристические (в глоссарии честно).
- **roadmap.py** — три этапа с критериями перехода го/стоп, шаблон по семейству.
  *Достойно:* дисциплина «лаборатория→пилот→внедрение». *Слабо:* **шаблон повторяется**
  на карточках одного семейства (см. Проблемы).
- **knowledge.py / analysis.py** — граф профиля потерь (элемент→класс→форма) и кривая
  раскрытия по крупности. *Достойно:* наглядная диагностика. *Слабо:* чисто визуализация.
- **intent.py** — из KPI достаёт целевой металл и ограничения (словарь: оборудование/реагенты/
  бюджет/качество). *Достойно:* детерминированный разбор, приватно (не в LLM). *Слабо:*
  словарный, незнакомую формулировку не поймёт (честно помечает «не распознано»).

### Трек Б (LLM только для понимания текста)
- **ingest.py** — принимает pdf/docx/xlsx/картинки → текстовые фрагменты (pymupdf, OCR по
  требованию). *Достойно:* один вход для разнородного. *Слабо:* схемы-диаграммы как топологию
  не читает — только текст/подписи (OCR).
- **extract.py** — LLM извлекает связи `A—тип→B` с ОБЯЗАТЕЛЬНОЙ дословной цитатой (гейт:
  цитата — подстрока фрагмента). Отбор фрагментов по покрытию терминов запроса.
  *Достойно:* цитатный гейт против галлюцинаций — ключевая честность трека Б. *Слабо:* выход
  ограничен окном чтения (max_chunks) и качеством модели.
- **kgraph.py / discover.py** — граф связей → разрывы Свонсона (A→B, B→C есть, A→C нет) +
  прямые связи, ранг = новизна·релевантность·бонус за промышленное действие. **Жёсткое
  заземление на металл фабрики** (символ + рудный минерал) — иначе просачивалось золото.
  *Достойно:* находит скрытые связи и режет офф-металл. *Слабо:* яд связей упирается в extract/LLM.

### A×B и обогащения
- **bridge.py** — сшивает диагноз трека А с конкретными узлами из СХЕМЫ фабрики (только файлы
  папки «Данные», не из общей литературы). *Достойно:* даёт адресность («насадки 12мм»).
  *Слабо:* работает только если загружена реальная схема и доступен LLM.
- **websearch.py** — веб-поиск дословной фразы, где упомянуто вмешательство и металл фабрики.
  *Достойно:* реальная цитата с URL, заземление на металл/минерал. *Слабо:* это **веб-упоминание,
  а не проверенное внедрение** — переименовано честно (было «Мировая практика», см. Проблемы).
- **openalex.py** — научные статьи по гипотезе с цитируемостью, заземлённые на элемент.
  *Достойно:* реальные источники, детерминированный отбор, без LLM. *Слабо:* релевантность
  ограничена выдачей OpenAlex.
- **litsupport.py** — привязывает дословные цитаты выданного корпуса к карточкам трека А
  (IDF-взвешивание → цитата по теме карточки). *Достойно:* per-гипотезная привязка. *Слабо:*
  зависит от наличия релевантного корпуса.

### Оформление / оценка / внешний слой
- **report.py / report_kb.py** — HTML с послойным SVG-графом и карточками (трек А / трек Б).
- **export.py** — JSON/CSV/Jira/PDF/DOCX поверх единого `serialize` → числа во всех файлах
  совпадают с HTML. *Достойно:* один источник правды.
- **judge.py** — LLM-судья: 5 осей (обоснованность, правдоподобие, релевантность, новизна,
  проверяемость) 1..5, кэш по отпечатку. *Достойно:* domain-агностичная рубрика, вне ранга.
  *Слабо:* нужен LLM; это оценка, не факт.
- **feedback.py** — вердикты эксперта из CSV → детерминированный ре-ранк («уже пробовали»
  опускается, не скрываясь). *Достойно:* цикл эксперта. *Слабо:* файл **глобальный**
  (`outputs/feedback.json`), не per-run — легко оставить устаревшую запись (см. Проблемы).
- **client.py** — единая точка внешних вызовов: ретраи, backoff, метрики (`run_metrics.json`).
  *Достойно:* всё измеряется в одном месте. **evaluate/benchmark/flex/batch** — оценка и прогоны.
- **config.py** — ЕДИНСТВЕННОЕ место всех констант (env-override, комментарии). Менять там.

## Метрики: как считаются (всё из ячеек)

- `impact = извл. тонны класса ÷ Σ извл. тонн по фабрике` — масштаб потери.
- `addressability = извл. тонны ÷ все тонны класса` — какая доля потерь вообще излечима.
- `clarity = тонны доминирующей формы ÷ извл. тонны` — один механизм или размазано.
- `confidence` — полнота данных под гипотезой; `feasibility` — нужно ли новое оборудование.
- `priority = impact·(0.5+0.5·addressability)·(0.7+0.3·clarity)·feasibility·confidence`
  — **наша эвристическая свёртка** (не факт; объяснена в глоссарии, эксперт пересчитает).

**Бенчмарк (детерминированный, 4 фабрики):** family-coverage recall **27/27 = 100 %**,
grounding **100 %** (каждая гипотеза привязана к ячейке), precision 60–100 %. Recall — доля
семейств эталонных вмешательств организаторов, воспроизведённых из данных без подсказки.

**Судья (LLM):** оценивает ВСЕ гипотезы (А+Б) по 5 осям 1..5; запускается отдельно, кэшируется.

## Проблемы (честно, по фактам)

1. **Абстрактность против конкретики эталона.** Эталон организаторов называет узлы фабрики
   («6-м мельницы», «насадки 12мм», реагент Finfix 300) — это требует знания СХЕМЫ фабрики,
   которого в отчёте по хвостам нет. Наши гипотезы — уровня «класса вмешательства»
   («доизмельчить класс»). Мост — A×B, но ему нужна реальная схема на входе.
2. **Дорожная карта повторяется.** `roadmap.py` — шаблон по семейству; на нескольких
   карточках одного семейства текст почти идентичен (отличается класс/металл). Не баг генерации,
   а свойство шаблона. Стоит доуточнять этапы узлами из A×B.
3. **«Похожие практики» ≠ внедрения.** Блок (бывш. «Мировая практика») — это веб-поиск
   дословной фразы, а НЕ проверенное применение на другой фабрике. Переименовано честно.
4. **Эксперт-фидбэк глобальный.** `outputs/feedback.json` общий на все прогоны; устаревшая
   запись помечает карточки «проверено» без видимого источника. Сброшен; нужен per-run/явный UI.
5. **Разнообразие при breadth=0 низкое** (~2 вмешательства): отражает руду (Ni заперт в
   пентландите повсеместно → измельчение), но выглядит монотонно. Разнообразие — по слайдеру.
6. **Ограничение «без оборудования» рубит почти всё:** раскрытие/классификация физически
   требуют оборудования, поэтому такой KPI честно помечает почти все гипотезы нарушающими —
   безоборудованных интервенций в правилах мало (реагентный режим).
7. **Яд трека Б упирается в LLM:** извлечение ограничено окном чтения и моделью; без ключа
   ветка Б не работает вовсе.

## Что улучшать дальше

- **Схема фабрики на вход + A×B по умолчанию** — главный рычаг конкретики (узлы, марки, диаметры).
- **OCR-препроцессинг** (Otsu/deskew на Pillow) и чтение координат боксов Yandex Vision —
  таблицы/регламенты перестанут перемешиваться (заготовка есть, не внедрено).
- **Модуль-критик** гипотез (риски, что проверить) — про доверие, не про разнообразие.
- **Ветвление механизмов трека А** для одного диагноза (несколько разных действий).
- **Предиктивная модель «крупность↔извлечение»** — пока мало точек на фабрику.

## Где что и почему (константы)

Всё в **`factory/config.py`**, каждая с env-override и комментарием. Основное:
- пути/кэши: `OUTPUTS_DIR`, `*_CACHE`, `RUN_CONFIG_PATH`;
- трек А: `SECONDARY_MIN_SHARE` (порог второго направления класса, 0.30);
- веб-порог гипотез: `webapp/config.py::DEFAULT_MAX_HYPS` (15) — «не флудить»;
- окно ветки Б: `webapp/config.py::DEFAULT_MAX_CHUNKS` (18), `MAX_CHUNK_CHARS` (3500);
- LLM: `YANDEX_MODEL`, `LLM_WORKERS`, `LLM_MAX_RETRIES`;
- веб-поиск: `WEB_MAX_HYPS`, `WEB_PER_DOMAIN`, `WEB_MIN_QUOTE_*` (гейт качества цитаты);
- OpenAlex: `OPENALEX_PER_HYP`, `OPENALEX_MAX_HYPS`;
- OCR: `OCR_MODEL` (page/table/handwritten), `OCR_LANGS`, `OCR_DPI`, `OCR_PDF_MAX_PAGES`;
- заземление трека Б на металл: `factory/discover.py::_EL_TERMS` (символ+минералы);
- линт: `pyproject.toml [tool.ruff]` — `ruff check` чистый; E702/E731 сознательно off (стиль).

## Экспертная оценка (металлургия, без натяжки)

**Сильное.** Диагностическая логика металлургически корректна и это лучшая часть: закрытый
пентландит/халькопирит → доизмельчение для раскрытия; раскрытый в тонком классе → извлечение
шламов/классификация; раскрытый крупный → доизвлечение флотацией. `impact` верно ставит
наибольшую *извлекаемую* потерю первой, `clarity` — честный сигнал «потеря объясняется одной
формой». Заземление всего на ячейки и цитатный гейт трека Б — это честность, которой часто нет.

**Слабое.** Конкретики уровня «заменить насадки 12мм» нет без схемы фабрики; разнообразие
по умолчанию низкое; дорожная карта повторяется; «похожие практики» — это веб-текст, не
внедрения; ветка Б и судья требуют рабочего LLM (в песочнице ключ не проходил — оценивалось
логикой и юнит-тестами).

**Вывод.** Как приоритизатор и диагност «где и в какой форме теряется металл» — решение
работает, воспроизводимо и не врёт числами (27/27, grounding 100 %). Как источник готовых
цеховых решений уровня эталона — пока нет: не хватает входа (схема фабрики), а не логики.
Разрыв закрывается кормлением схемы и сшивкой A×B, а не «фичами поверх».
