# Фабрика гипотез

Инструмент принимает базу знаний (Excel-отчёты, PDF/DOCX-литературу) и целевой KPI,
на выходе даёт ранжированные проверяемые гипотезы с обоснованием и ссылкой на источник.
Архитектура — **гибрид**: детерминированное ядро рассуждения + LLM только для понимания
неструктурированного текста (с цитатным гейтом). Логика диагностики и метрики
воспроизводимы; LLM не участвует в выводах, где есть структура.

## Логика работы

### Приём (ingest.py)
Загружается что угодно: PDF (pymupdf), DOCX/TXT (xml/plain), XLSX/CSV (openpyxl/csv).
Каждый файл → фрагменты `Chunk{text, source, locator, kind, meta}`; `meta` несёт
метаданные (файл, страница/лист, дата). Структура на входе не хардкодится.

### Диспетчер (flex.py)
Каждый файл маршрутизируется по типу:
- **отчёт по хвостам** (xlsx, распознаётся пробным чтением) → детерминированная ветка;
- **прочий текст** (литература, отчёты) → LLM-ветка извлечения;
- эталонные `Гипотезы*.docx` исключаются из знания (это ответы, не источник).

### Ветка A — детерминированная диагностика хвостов
```
reader.py    xlsx → профиль: классы крупности × минеральные формы × тонны (+ ячейка-провенанс)
             парсинг по подписям-якорям, канонизация классов, #REF!→None, валидация баланса
analysis.py  кривая раскрытия (закрытый/раскрытый Pnt по крупности), «обрыв раскрытия»,
             trade-off (измельчение ↔ рост -10 шламов), форм-разбивка (что физически извлекаемо)
rules.py     (доминирующая форма + крупность) → семейство вмешательства  [читаемая таблица правил]
metrics.py   impact (доля потерь) · addressability (излечимость) · clarity (ясность механизма) ·
             feasibility · confidence → priority. Всё безразмерно, из данных, без цен.
generator.py карточка ЕСЛИ/ТО/ПОТОМУ ЧТО + заземление до ячейки
```
Без LLM, ~0.03 c, тот же файл → тот же результат.

### Ветка B — извлечение из текста → граф → открытие
```
extract.py   LLM читает фрагмент, возвращает связи (subject —тип→ object) с ДОСЛОВНОЙ цитатой.
             Тип связи — из закрытого словаря {повышает/снижает/не_влияет/связан} → знак
             детерминирован. Цитатный гейт: цитата обязана быть подстрокой фрагмента, иначе
             связь отбрасывается. Результат кэшируется → downstream воспроизводим.
             Отбор фрагментов — по релевантности KPI (лексический префильтр).
kgraph.py    связи → канонический граф (networkx), нормализация сущностей, провенанс+метаданные
discover.py  разрывы Свонсона (A→B, B→C, нет A→C) + прямые рычаги (связь к KPI-сущности);
             ранг = новизна (редкость узла) × релевантность KPI. Детерминированно поверх кэша.
```
LLM только извлекает; вывод (граф, разрывы, ранг) детерминирован после кэша.

### Отчёт и оценка
- `report.py`/`glossary.py` → самодостаточный HTML: граф (SVG), кривая раскрытия, форм-таблица,
  карточки, глоссарий метрик. `outputs/<фабрика>_гипотезы.html`.
- `benchmark.py` → сверка гипотез со всеми эталонными `Гипотезы*.docx` по семействам вмешательства.
- `docs/build_guide.py` → PDF-гайд разработчика (reportlab).

## Запуск
```bash
uv sync
# всё сразу: 4 отчёта (детерминизм) + литература (LLM-извлечение)
uv run python -m factory.flex materials --kpi "снизить потери никеля с хвостами" --max-chunks 24
# одна фабрика с HTML
uv run python -m factory "materials/fabrics/ТОФ/Хвосты ТОФ_2.xlsx"
# сверка со всеми эталонами
uv run python -m factory.benchmark
```
Детерминированное ядро работает без сети/ключа. LLM-ветка требует `YANDEX_API_KEY` в `.env`.

## Результаты (реальные данные)
- Детерминированная диагностика: 4 фабрики, гипотезы ранжированы по impact, каждое число —
  до ячейки. Golden-сверка: **23/27 = 85%** (ТОФ/КГМК 100%, НОФ_вкр 83%, НОФ_мед 62%).
- Литературная ветка: из справочника по флотации извлекаются связи с цитатой до страницы,
  формируются гипотезы-механизмы (pH → деактивация флотации; измельчение → раскрытие сростков).

## Соответствие критериям ТЗ

| Критерий | Статус | Как закрыт |
|---|---|---|
| Вход: KPI + база знаний | ✅ | KPI-строка + папка любых файлов |
| Приём/парсинг литературы (PDF/статьи/отчёты) | ✅ | ingest.py (pymupdf/docx) |
| Импорт структурных данных | ✅ | reader.py (xlsx-отчёты), csv/xlsx как таблицы |
| Метаданные (источник/дата/страница) | ⚠️ | file/page/sheet/date; автор — нет |
| Извлечение сущностей и связей | ✅ | extract.py (LLM + цитатный гейт) |
| Пробелы/паттерны | ✅ | разрывы Свонсона + прямые рычаги (discover.py) |
| Аналогии / контрфактуал / предсказание | ⚠️ | разрывы ≈ аналогии; контрфактуал/ML — нет |
| Ранжирование (новизна/реализуемость/эффект/риск) | ✅ | детерминированные метрики (impact/novelty/feasibility/confidence) |
| Обоснование + ссылки на источник | ✅ | заземление до ячейки (хвосты) / цитаты+страницы (текст) |
| Визуализация связей (граф) | ✅ | SVG-граф + кривая раскрытия в HTML |
| Оценка неопределённости | ⚠️ | confidence + валидация парса; противоречия не разрешаются |
| Прозрачность/интерпретируемость | ✅ | правила и метрики читаемы, «цитата» = координата/подстрока |
| Гибкость входных данных | ✅ | гибридный приём разнородных/неполных данных |
| Надёжность к шуму | ⚠️ | #REF!→None, цитатный гейт, валидация баланса; без разрешения противоречий |
| Производительность (минуты) | ✅ | ядро ~0.03 c; извлечение — минуты, кэшируется |
| Масштабируемость на новые области | ⚠️ | текст-ветка доменно-независима; хвосты-ветка = reader+rules под формат (нужен schema-адаптер) |
| Экспорт PDF/DOCX/CSV/JSON, Jira | ⚠️ | HTML-отчёт + PDF-гайд; бизнес-PDF/DOCX и задачи — нет |
| Мультиязычность RU/EN/CN | ⚠️ | RU; EN — через LLM; CN не проверено |
| Безопасность (локально) | ⚠️ | ядро локально без ключа; LLM-ветка — облако Yandex |
| Экспертная настройка весов | ⚠️ | веса/цены/правила редактируемы в коде, не в UI |
| Дорожная карта эксперимента | ❌ | не реализовано |
| Обучение на фидбэке | ❌ | не реализовано |

## Структура
```
factory/
  ingest.py extract.py kgraph.py discover.py flex.py   ← гибкая ветка (текст → граф → открытие)
  reader.py analysis.py rules.py metrics.py generator.py pipeline.py  ← детерминированная ветка (хвосты)
  llm.py report.py glossary.py benchmark.py evaluate.py docs/build_guide.py
materials/   fabrics/<Ф>/ (Хвосты+Гипотезы) · reference/ (books/schemes/regulations)   [вне git]
outputs/     сгенерированные HTML/кэш   [вне git]
```
